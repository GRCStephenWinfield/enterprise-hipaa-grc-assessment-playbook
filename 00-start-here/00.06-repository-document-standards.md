# Purpose

This document establishes the documentation standards used throughout the Enterprise HIPAA Cybersecurity Assessment Playbook.

These standards ensure every document is presented consistently, is easy to navigate, and communicates information in a professional manner. Consistency improves readability, simplifies maintenance, and supports repeatable assessment execution.

This standard applies to every document within this repository unless a document specifically states otherwise.

# Standard Document Sections

Unless otherwise justified, documents should follow this order:

1. Purpose
2. Objectives
3. Assessment Planning Snapshot
4. Prerequisites
5. Inputs
6. Activities
7. Outputs
8. Completion Criteria
9. Navigation

Operational documents may also include:

- Consultant Notes
- Best Practices
- Common Pitfalls
- Red Flags
- References

---

# Heading Standards

Use Markdown headings consistently.

```text
# Document Title

## Major Section

### Subsection
```

Avoid skipping heading levels.

---

# Markdown Formatting Standards

Use:

- Tables for structured information.
- Bullet lists for unordered items.
- Numbered lists for sequential activities.
- Code blocks for filenames, commands, workflows, and examples.
- Horizontal rules (`---`) to separate major sections.

Avoid excessive formatting that reduces readability.

---

# Document Status Values

Approved status values are:

- Draft
- In Review
- Approved
- Archived

Only one status shall be assigned to a document at any time.

---

# Versioning Standard

Version numbers shall follow semantic progression.

| Version | Meaning |
|----------|---------|
| 0.x | Working draft |
| 1.0 | Initial approved release |
| 1.x | Minor revisions |
| 2.0 | Major revision |

---

# Repository-Wide Conventions

The following conventions apply throughout the repository:

- Filenames use lowercase letters.
- Words are separated with hyphens.
- Files begin with their assessment sequence number.
- Documents are completed in numerical order.
- Assessment conclusions must be supported by evidence.
